# 真实系统还原要点(密度与组件模式)

目的:让生成的静态 demo 在"第一眼"就像公司真实后台系统,而不只是通用管理模板。以下模式来自真实系统截图(PDMS/QMS/SRM/George Design)与 Figma 七份规范的交叉核对。全部已内置在 `assets/static-kit` 的 tokens/shell/components 与样例页中,生成时复用对应类即可,**不要退回通用大间距/蓝色 Ant Design 风格**。

## 1. 整体密度(关键差异)
真实系统比通用模板**紧凑得多**。遵守 tokens:
- 顶栏 48px;表头 40px;数据行 44px;行内上下留白 6px;控件高 32px。
- 正文 12px、页签/卡片标题 13px、模块/页面标题 14/16px;行高 1.5。
- 圆角一律 2/4/6(避免 8 以上的"大圆角圆润感");间距用 4 的倍数。
- 一屏尽量多信息:列表默认一页 8~20 行,详情信息栅格 4 列。

## 2. 顶部操作区(`.sys-top`,shell.js 自动渲染)
- 左:圆形 `G` logo + 系统名(14px 粗体)。
- 中:刷新图标 + **工作页签**(当前页面名 + `×`,`.sys-worktab`),体现"多页签工作区"。
- 右:**租户标**(`cfg.tenant`,如"敬城",绿色 `.sys-tenant`)+ 一排圆形图标(应用/搜索/通知/主题/深色)+ 身份胶囊(头像+姓名·角色)。
- 图标用无边框圆形 hover 浅底,不要做成带边框的方块大按钮。

## 3. 内容页签(`.list-head` + `.list-tabs`)
- 小号文字页签(13px),激活态=绿色文字 + 2px 绿色下划线,不用大色块按钮。
- 带数量角标(`.count`,>99 显示 99+)。右侧放高级筛选漏斗 `.icon-btn`。

## 4. 搜索筛选区(两种,按复杂度选)
- **一体式**(默认,最像真实系统):`.filter-inline > .search-combo([下拉|输入框…]) + 重置 + 查询`。查询为**绿色主按钮**。适合"一个主搜索条件"的列表。
- **栅格式**:条件多时用 `.filter-grid`(2/3/4/5 列等分,标签在控件上方),末列放查询/重置/更多(R088)。

## 5. 操作工具栏(`.op-bar`)
- 左 `.op-left`:主操作用**绿色** `.btn.primary`,其余白底描边;常带下拉箭头 `▾`(`<span class="caret">▾</span>`),如 上传产品▾ / 全量下载▾ / 删除▾ / 修改▾。直接展示≤5 个,其余收"更多"(R094/R095)。
- 右 `.op-right`:`已选 N 条` + 导出 + 列设置齿轮 `.icon-btn`。

## 6. 表格(`.g-table`)
- 列顺序贴近真实:选择框 → 序号 → 业务主键(如 产品唯一ID,长数字)→ 名称 → 关联编号 → 型号 → 英文名 → 数值(右对齐)→ 状态标签 → **主图缩略图**(`.cell-thumb`,48×34 圆角,占位用内联 SVG)→ 操作。
- 表头浅灰底 40px;行 44px;hover 行浅绿底。
- 文本单行省略(`.ellipsis`),金额/数量右对齐(`.num`)。
- **操作列固定在右侧**(`.col-op` sticky),内放一排**绿色文字链**(详情▾ / 编辑 / 发起补充 / 导入图片),≤5 个,其余收更多(R108/R111)。

## 7. 分页 + 统计(`.list-foot`)
- 左:`共 N 条记录`(`.list-stats`)。
- 右:每页条数下拉(`.page-size`,8/12/20 条/页)+ 完整分页器(`.pager`:首页 `|‹` / 上页 `‹` / 页码 / 下页 `›` / 末页 `›|`,当前页绿色实心)。

## 8. 详情(两栏)
- `.detail-cols = 1fr 300px`:左 `.detail-main`(步骤 `.detail-steps` + 基本信息 `.info-grid` 4 列 + 关联表格固定高度滚动),右 `.detail-side` 放**流程记录时间线** `.flow-panel/.flow-item`(圆点 + 标题 + 时间 + 头像·姓名·角色 + 备注,末节点灰色 pending)。
- 模块标题 `.section-head h3` 左侧带 3px 绿色竖条。
- 键值用行内式 `.info-item`(k 后自动加"："),空值显示 `-`。

## 9. 表单
- 模块标题带绿色竖条;`.form-grid` 默认 3 列,同行顶部对齐;必填红星;控件下方灰色提示;异常态红框保留内容。吸底操作栏(取消/保存,保存为绿色主按钮)。

## 10. 配色(贴合真实系统)
- 主按钮/主链接/激活态/查询:**绿色**(`--g-btn-primary-bg` 默认 #74BF28)。注:这与 Figma 设计语言 R018"主按钮近黑 #222"不同——此处以真实系统视觉为准;若需严格遵循 Figma,把 `--g-btn-primary-bg` 改为 `var(--g-primary)` 即可。
- 文本 #333/#666/#999;状态点标签 成功绿/进行蓝/错误红/预警橙/中性灰;页面底 #F7F7F7,卡片白,描边 #E2E2E2/#EEE。
- 不使用 Ant Design 默认蓝(#1677ff)作为主色。

## 11. 浮层:弹窗 / 抽屉 / 审批面板(防错位,统一用套件方法)
真实系统里"查看任务详情、上传处理结果、确认(含版本记录)"等都是**居中弹窗(modal)**,不是贴边铺开的面板——后者正是常见的"样式错位"。套件已内置三种浮层,**一律用方法调用,禁止手写绝对定位浮层**:
- **居中弹窗 `Shell.openModal({title,size,body,actions,onOpen})`**(`.modal`):相对**视口**居中、带遮罩、`max-height:calc(100vh-48px)` 内部滚动、最高 `z-index`;头部浅绿标题栏(标题 + 全屏切换 + 关闭)、底部右对齐动作栏(取消/确定、取消/暂存/同意等,主操作绿色);尺寸 `sm 420 / md 640 / lg 900 / xl 1100 / full`,宽度自动收敛到 `100vw-间距`,**绝不撑破或出横向滚动条**。用于:查看全貌、表单(上传结果)、二次确认、版本记录。
- **右侧抽屉 `Shell.openDrawer`**(`.drawer`):列表行编辑/新增、侧栏速览。
- **审批面板 `Shell.openApproval`**(`.drawer.approval`):OA 多节点审批(左详情+右节点时间线)。
- **防错位要点**:浮层都 `position:fixed` 挂到 body/overlay 层,不进内容流、不相对内容区偏移;因此导航收起/展开都不影响居中。一屏只开一个主浮层,modal 用完 `Shell.closeModal()`。

## 12. 待办 / 审批流(OA 场景,`todo.html` + `Shell.openApproval`)
真实系统的待办点开后进入"审批详情",是一个**从左侧弹出、几乎铺满内容区的宽面板**(左侧留一条窄缝露出背后列表):
- **待办列表**(`todo.html`):页签 全部/我发起的/待我审批/已逾期(带数量角标)+ 一体式搜索 + 表格(序号/单据编号/流程名称/业务类型/当前节点/发起人/紧急度/提交时间/状态/操作[审批])。点击行或"审批"进入审批面板。
- **审批面板**(`Shell.openApproval({title,subtitle,sections,nodes,actions})`,`.drawer.approval` + `.approval-flow`):
  - 左 `.af-main`:**分组详情**(基础信息 / 业务信息 / 客户与预算 / 对接与协作…),每组 `.section-head`(绿色竖条)+ `.info-grid`(3~4 列,空值 `-`)。
  - 右 `.af-side`:**流程记录时间线**(`.flow-item`),每节点含:节点名、时间、处理人头像·姓名·角色、**耗时**(`.f-dur`,如"25天21小时27分49秒")、**状态徽标**(`.node-badge`:已通过绿 / 已跳过灰 / 待审批)、**当前节点绿色高亮**(`.node-current`),当前节点可带"更多 ▾"。
  - 右下固定 `.af-actions`:**驳回**(红描边 `.danger-outline`)/ 转交 / **同意**(绿色主按钮)。点击要真实生效:toast 反馈 + 关闭面板(真实开发里对应提交审批接口)。
- 窄窗(容器 <900px)自动上下堆叠(详情在上、审批节点在下)。

## 13. 其他真实元素(按需)
- 右下浮动圆钮(`.fab`,如 疑难解答 / 表单设计)。
- 顶栏深色/主题切换图标(演示态可只 toast)。
- 列表的"导出/列设置/批量操作"等占位按钮,点一下用 toast 提示"演示占位",避免空按钮无反馈。
