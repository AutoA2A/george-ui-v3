# 常见异常与预判清单(其他 AI 生成 demo 前必读)

本清单把历次测试中真实出现过的 demo 异常,归纳为"现象 → 根因 → 套件已内置的预防 → 你(AI)必须遵守"。
目标:**下一个 AI 直接避开这些坑,一次生成就正常。** 生成前通读一遍,交付前对照自查。

> 口诀:**浮层只用套件方法、不手写定位;不悬浮覆盖内容;不加载即弹;相对路径离线跑;品牌不乱起;部署全自动不要 key;改完等缓存+硬刷新。**

---

## 一、浮层 / 遮挡(最高频)

1. **右下角浮动按钮(FAB)盖住表格底部行的操作列 → "最后几行按钮点不动"。**
   - 根因:绝对定位 `position:absolute; z-index` 的悬浮按钮压在内容之上,拦截点击。
   - 预防:**套件已删除 FAB(`.fab`/`.fab-group`)**。真实系统也没有此元素。
   - 必守:**禁止**再加任何悬浮覆盖内容的按钮/球。辅助入口一律放进顶部操作工具栏。

2. **手写绝对定位浮层错位(塞进内容流 / 贴边硬写 / 相对内容区偏移)。**
   - 预防:只用 `Shell.openModal / openDrawer / openApproval`——都是 `position:fixed` 挂最高层、带遮罩、内部滚动,相对**视口**定位。
   - 必守:不要自己写 modal/drawer 的定位。

3. **抽屉/审批面板宽度不对**(曾出现"从左 `left:40px` 贴边近满屏""又太窄留大片空白")。
   - 预防(已固化在 `components.css`,不要改回去):普通抽屉 `.drawer=min(1040px,86vw)`;审批/详情 `.drawer.approval=min(1280px,94vw)`,右侧滑入、两栏 `minmax(0,1fr) 340px`、窄屏(容器<760px)自动堆叠。
   - 必守:详情/审批是"低密度宽松阅读"场景(Figma 规范确认),信息分组用多列铺满、避免空白;但不要从左贴边。

---

## 二、导航

4. **二级导航标题换行/错位**(如「任务管理」被挤成两行、收起按钮错位)。
   - 根因:二级栏太窄,放不下"标题 + 收起按钮 + 内边距"。
   - 预防:`--g-secondary-w=150px`;`.sys-secondary h2` 已 `white-space:nowrap`+省略;头部用 `.sec-head`,按钮 `flex:none` 不压缩标题。
   - 必守:一级/二级标题尽量 ≤5 个汉字;更长时自行加宽 `--g-secondary-w`,别让它换行。

5. **「系统管理」菜单树缺失 / 系统设置入口看不到。**
   - 根因 A:`sys-data.js` 的 `menusFromNav()` 在 shell 注入「系统管理」导航之前运行,菜单树里就少了它。预防:`menusFromNav()` 已**显式补**一个「系统管理」目录(角色/用户/菜单)。
   - 根因 B(更常见):**浏览器/CDN 缓存**,其实代码已生效。预防:见第五节,改完务必硬刷新。
   - 必守:系统设置齿轮 + 「系统管理」一级导航由 `shell.js` 自动注入,**不要删、不要改 nav-config 去掉它**。

6. **无子菜单的一级导航却渲染出空的二级区。**
   - 预防:`shell.js` 对无 children 的一级直接直达页面、不渲染二级(`data-secondary='none'` 宽度归零)。必守:别手动塞空二级栏。

---

## 三、弹窗滥用 / 假功能

7. **页面加载就自动弹窗**(如"本页面向 XX 角色,请去 YY 页")。
   - 必守:**禁止加载即弹**。引导/提示用页面内联提示条或 `Shell.toast`。弹窗只能由用户点击触发。

8. **纯文字"演示占位 / 仅示意"弹窗或按钮充数。**
   - 必守:按钮要有真实本地效果(过滤、打开抽屉、表单回填校验、跨页 `?id=` 跳转)。占位操作**至少**给 `Shell.toast` 反馈,不要只弹一个"仅示意"的框。已有菜单不得链接空页面。

---

## 四、离线 / 路径(破坏"双击即开")

9. **绝对路径 / 联网 CDN / ES `import` / `fetch` 本地文件 / 需要起端口的 SPA。**
   - 现象:双击 `index.html`(`file://`)打不开、白屏或资源 404。
   - 必守:**全部相对路径** + `<script>` 标签 + DOM 渲染。禁止 `file:///`、`/assets/…` 绝对路径、`127.0.0.1`、`http(s)://` 外链、`import`/`fetch`。图片用内联 SVG/色块占位。(注:内联 SVG 里的 `xmlns="http://www.w3.org/2000/svg"` 是命名空间,不是网络请求,允许。)

---

## 五、部署 / 令牌 / 缓存

10. **向用户索取 GitHub key / 把部署做成"需要用户给 token"的交互。**
    - 必守:**完全自动部署**。直接 `py scripts/deploy.py <demo目录>`;脚本自动读令牌(环境变量 → `.secrets/github.token` → `%USERPROFILE%\.george-ui\github.token`)。**不要询问、索取、打印、复述令牌。** 仅当脚本明确报"未找到令牌"才一句话让用户跑一次 `github_setup.py`。

11. **部署校验误判**(线上其实已 200,却报"未通过校验")。
    - 根因:早期 `deploy.py` 只读响应前 400 字节,中文标题把校验标记挤到后面。预防:已改为读 64KB。必守:别把超时/404/preflight 失败说成"已部署成功"。

12. **"改了线上没变 / 页面 404 / 系统设置不见了" —— 多数是缓存,不是 bug。**
    - 根因:GitHub Pages CDN 传播有延迟(数十秒),叠加浏览器缓存。
    - 必守:重新部署后**等待片刻 + 硬刷新(Ctrl/Cmd+F5)**再判断;交付时主动提醒用户硬刷新。确认线上 `verified=true`、HTTP 200 即为成功,不要据此回改代码。

---

## 六、品牌 / 内容

13. **左上角品牌名乱起 / 沿用样例 `PDMS`。**
    - 必守:知道系统名就用系统名(如「GDS 任务管理」);不知道统一用 `George`(或 `George Design`);有需求文档(如 `product-requirements.md`)以文档的项目代号/品牌为准。**禁止**出现样例遗留的 `PDMS`。

14. **没按需求文档做 / 默认套"产品列表"。**
    - 必守:有需求文档就严格按文档的页面、字段、流程、身份做;模糊需求先补"建议方案"让用户确认(铁律 2),不要默认生成产品列表。
